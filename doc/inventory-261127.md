# 分類に使っていない担体の棚卸し（REQ-INV-01）

対象仕様書: `doc/261127_plan-false-classification-fix.md` §7.1。
この表は「現行は分類に使わない」担体と、その理由を固定するもの。**将来これらを分類に
使う場合は、§2.2 の強さ定義（キー＋値パターン、値検証、弱は複合のみ）に従って
値検証を設計してから**着手すること。存在だけ・汎用値だけで確定させてはならない。

| 担体（source / keyword） | 現行の扱い | 理由 | 固定テスト |
|---|---|---|---|
| EXIF `Make`（`Make`） | 分類に使わない | カメラ／機器名で、生成ツールを書く欄ではない。汎用すぎて誤爆する | N-01〜N-03 系、T-14 |
| EXIF `Artist`（`Artist`） | 分類に使わない | 人名・任意文字列。AI 生成の証拠にならない | T-14 |
| EXIF `XPComment`（`XPComment`） | 分類に使わない | Windows の汎用コメント欄。編集ツールの注記が入る | T-14 |
| IPTC `Caption/Abstract`（`Caption/Abstract`） | 分類に使わない | 報道・写真のキャプション。Lightroom 等が普通に書く（N-05 と同型） | T-14 |
| XMP `title`（`title`） | 分類に使わない | 作品タイトル。ツール名も生成宣言も含まない | T-14 |
| PNG `Title`（`Title`） | 分類に使わない | 同上（汎用テキスト） | T-14 |
| PNG `Source`（`Source`） | 分類に使わない | 出所の自由記述。NovelAI 以外も書く | T-14 |
| XMP `description`（`description`） | 分類に使わない（U-7 の結論） | MJ の XMP のみ画像を捕捉する条件が見つからず、汎用 dc:description を
  Midjourney とみなすと N-05 を再び誤検知するため | N-05、P-18、T-14 |
| XMP `label`／`Nickname` 等の非対応フィールド | そもそも抽出しない | 抽出対象外（`vlm`／`fast_meta` の XMP フィールド表に無い） | 対象外 |
| PNG `Software`（`Software`） | **値照合のみ**（存在は数えない） | ツール名の表（REQ-CLS-10）に一致する場合だけシグナル | N-01〜N-03、P-11 |

## 付随事項

- **C2PA（REQ-INV-02）**: 実装しない。`Source::C2pa` は fast_meta の enum の予約に留まり、
  C2PA の生成宣言だけを持つ画像は現行ではどのレコードも生成されない（分類は空振りする）。
  これは既知の制限であり、T-15 で現状を固定する。対応済みと誤認させる表示は置かない。
- **16MB 上限（REQ-EXT-12）**: EXIF／XMP パケットの 16MB 上限は資源保護として維持し、
  上限超過は「その担体が 0 件」になる（fast_meta 側 T-30 で固定）。上限超過が分類に
  影響したかを利用者が知る手段（デバッグ出力等）は将来課題としてこの表に記録する。
