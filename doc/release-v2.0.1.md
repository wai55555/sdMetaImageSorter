# sdMetaImageSorter v2.0.1

v2.0.0 の分類・移動の意味論は変えず、sorter 単独の走査コストを削減したメンテナンスリリースです。

## 変更内容

- **走査の二重解消**: 旧 `webui_image` を探す全ツリー走査と、`WalkDir` による画像収集の
  全ツリー走査を、1 回の再帰走査（`collect_directory_images`）に統合しました。
- **`create_dir_all` の集約**: 画像1枚ごとに呼んでいた整理先フォルダの作成を、
  `DirectoryCache` により整理先ごとに1回へ削減しました。
- **`walkdir` 依存を削除**。

旧フォルダ移行、出力フォルダの走査除外、同名ファイルの上書き保護、移動/コピーの
フォールバック、終了コードは v2.0.0 から変更していません。

## ベンチマーク

同一マシン・1,000枚・移動モード・ウォームアップ1回＋3回計測の中央値。

| 配置 | v2.0.0 | v2.0.1 | 改善 |
|---|---:|---:|---:|
| フラット（1ディレクトリ、1,000枚） | 0.131 s | **0.090 s** | 約1.46倍 |
| ネスト（100ディレクトリ、各10枚） | 0.084 s | **0.080 s** | 約1.05倍 |

v1.1.0 + `fast_meta.exe` のベースライン（1.673 s）から約12倍高速という
v2.0.0 の性能は維持しています。

## 配布サイズ

| バージョン | サイズ |
|---|---:|
| v2.0.0 | 1,480,192 bytes |
| v2.0.1 | **1,434,112 bytes** |

`walkdir` 依存の削除などにより 46,080 bytes（約3.1%）減。

## 検証

- `cargo build --release --locked` / `cargo test --locked`: 緑
- ユニットテスト17件・統合テスト2件が成功
  - 1回の走査で画像収集と旧フォルダ移行が行われること
  - `DirectoryCache` が冪等であること
  - 旧 `webui_image` が移行され、移行先を再走査しないこと
- 等価性コーパス13枚の仕分け結果は v2.0.0 と一致
- `sd_meta_sorter.exe --version`: `sd_meta_sorter 2.0.1`

## 互換性

- CLI オプション、既定フォルダ名、分類規則、終了コードに変更はありません。
- v2.0.0 と同じく、ビルドには C コンパイラが必要です（`zlib-ng` のネイティブビルド）。

```bash
cargo build --release --locked
```

詳細は `doc/phase5/optimization.md` を参照してください。
